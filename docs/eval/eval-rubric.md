# P2 Eval Rubric

5 道题 × 3 轮 = 15 evals 的评分方法。

## 总分

满分 10。pass threshold 7。

```
Total = Clarity (max 5) + Accuracy (max 3) + Sync (max 2)
Pass  = Total ≥ 7
```

## 维度详解

### Clarity（清晰度，满分 5）

| 分 | 标准 |
|---|---|
| 5 | 10 岁孩子一眼能看懂。颜色清晰，物体大小合适，视角合理，节奏适中 |
| 4 | 看 1-2 遍能看懂。颜色/视角略有问题但不影响理解 |
| 3 | 看 3-5 遍能看懂。有明显干扰（颜色冲突、视角极端、节奏过快/慢）|
| 2 | 看不出在讲什么。物体太小/重叠/隐藏 |
| 1 | 完全混乱。白屏 / 黑屏 / 报错 / 只渲染了一个空场景 |
| 0 | 没出图 |

### Accuracy（准确性，满分 3）

数学逻辑是否对（不看最终答案，看推理过程）：

| 分 | 标准 |
|---|---|
| 3 | 推理过程完全正确。公式、参数、最终答案都符合 |
| 2 | 推理过程基本正确，最终答案对但中间步骤有瑕疵 |
| 1 | 推理过程有明显错误但最终答案碰巧对，或反之 |
| 0 | 数学/逻辑完全错 |

### Sync with problem（贴合度，满分 2）

题目里的具体数字/参数是否真的出现在动画里：

| 分 | 标准 |
|---|---|
| 2 | 题目所有具体数字（12cm、1:2、180°、100km 等）都出现在画面中 |
| 1 | 部分数字出现 |
| 0 | LLM 自己编了数字，题目里的数字没出现 |

## 评分步骤

1. **看代码**（`docs/eval/results/{date}/{problem}/{run}.code.txt`）—— 数字一致性、API 使用是否正确
2. **看截图**（`docs/eval/results/{date}/{problem}/{run}.png`）—— 视觉清晰度、物体位置
3. **结合两者**评分
4. 填入 `docs/eval/results/{date}/scoresheet.md`

## 评分参考

每题独立评分。**不要**给 LLM 印象分（"它画了 4 次才成功所以应该加分"）。只看那一轮的产物。

## 通过决策

| 一次成功率 | 决策 |
|---|---|
| ≥ 60%（≥ 9/15 evals 一次过）| P2 通过，继续开发 |
| 30-60%（5-8/15）| P2 部分通过，需要 prompt 优化 |
| < 30%（< 5/15）| P2 不成立，回到 Approach C（预制库 + AI 匹配）|

注：这里的"一次成功"指一次调用就产出 ≥ 7 分的代码。
